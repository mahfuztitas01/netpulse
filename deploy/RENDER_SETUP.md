# Deploy NetPulse to Render (free, from GitHub)

This runs the dashboard **24/7 in the cloud**, straight from your GitHub repo —
your own PC no longer needs to be on. No credit card required.

Stack:

| Piece | Service | Why |
|-------|---------|-----|
| App | **Render** free web service | auto-deploys from GitHub |
| Database | **Neon** free Postgres | Render's free disk is ephemeral, so data must live outside |
| Keep-awake | **cron-job.org** (or UptimeRobot) | free web services sleep after ~15 min idle |

> ⚠️ **What a cloud host can and cannot monitor**
> - ✅ Public targets: your ISP gateway IP, public IPs, websites, DNS servers
> - ❌ Office LAN devices (`192.168.x.x`) — a cloud server cannot reach a private
>   network. For those you still need a VM + WireGuard tunnel (see
>   `AZURE_SETUP.md` / `WIREGUARD_SETUP.md`).
> - ❌ Raw ICMP ping is usually blocked on free hosts. Prefer **TCP** or **HTTP**
>   checks in the cloud; keep **Ping** for a VM deployment.

## Step 1 — Create the free Postgres (Neon)

1. Go to <https://neon.tech> → **Sign up** (GitHub sign-in works, no card)
2. Create a project, region **AWS ap-southeast-1 (Singapore)** (closest to BD)
3. Copy the **connection string**. It looks like:

   ```
   postgresql://neondb_owner:AbC123xyz@ep-cool-name-123456.ap-southeast-1.aws.neon.tech/neondb?sslmode=require
   ```

   Keep this secret — it is your database password.

NetPulse converts that URL automatically to the `postgresql+asyncpg://…?ssl=require`
form the async driver needs.

---

## Step 2 — Deploy on Render

1. Go to <https://render.com> → **Get Started** → sign in **with GitHub**
2. **New +** → **Blueprint**
3. Pick the repository **`mahfuztitas01/netpulse`**
   (Render reads `render.yaml` from the repo — keep the blueprint path default)
4. Render asks for the values marked `sync: false`:

   | Key | Value |
   |-----|-------|
   | `DATABASE_URL` | paste the **Neon** connection string from Step 1 |
   | `FIRST_ADMIN_PASSWORD` | your own admin password (min 8 chars) — **write it down** |
   | `FIRST_ADMIN_EMAIL` | your email, e.g. `mahfuztitas01@gmail.com` |

5. Click **Apply** / **Create**. First build takes ~3–5 minutes.
6. Open the service URL, e.g. `https://netpulse-xxxx.onrender.com`

Log in with `admin` + the password you set. You will be asked to change it on
first login.

### If the build fails

- Check the **Logs** tab. Most common cause: `DATABASE_URL` still points at
  SQLite or contains a typo.
- `pip install` timeouts are normal on the first try — hit **Manual Deploy →
  Deploy latest commit** again.

## Step 3 — Keep it awake (important)

Render's free web service **sleeps after ~15 minutes without HTTP traffic**.
While asleep the monitor engine is stopped, so no checks and no alerts run.

Create a free pinger:

1. Go to <https://cron-job.org> → sign up (free)
2. **Create cronjob**
   - URL: `https://YOUR-APP.onrender.com/health`
   - Schedule: **every 5 minutes**
3. Save

Now the service stays awake and the engine keeps monitoring.

> A single free Render service running 24/7 is ~730 hours/month, inside the
> 750-hour free allowance.

---

## Step 4 — Configure alerts in the dashboard

The `SECRET_KEY` is generated by Render, so everything you save in the UI is
encrypted with a key that survives restarts. Configure:

1. **Alerts** → paste your bot token → **Find chat ID** → set the default chat
2. **Groups** → create `client01` / `client02` / `client03` with their chat ids
3. **+ Add Device** → pick the **Alert group** for each device
4. **Test** each group to confirm delivery

---

## Step 5 — Point your stable link at it

The GitHub Pages link `https://mahfuztitas01.github.io/netpulse-link/`
currently forwards to your Cloudflare quick tunnel. Once Render is live, point
it at the Render URL instead:

```powershell
cd netpulse
.venv\Scripts\python.exe scripts\update_public_link.py https://YOUR-APP.onrender.com
```

## Troubleshooting

| Symptom | Fix |
|---------|-----|
| 502 / "Application failed to respond" | Check Render logs; usually a bad `DATABASE_URL` |
| Login says "invalid credentials" | `FIRST_ADMIN_PASSWORD` only applies on the **first** boot of an empty DB. If the DB already has users, use those. |
| Devices all show DOWN | ICMP is blocked on free hosts — switch those checks to **TCP** or **HTTP** |
| Alerts stop after ~15 min | The pinger (Step 3) is not running or the URL is wrong |
| Data disappeared after a redeploy | `DATABASE_URL` is pointing at SQLite, not Neon |
